## **Digital Master Notebook**

### Technical & Design Specification for LLM-Driven Implementation

---

# 🧱 ЧАСТЬ 1

## 1. Цель документа и роль LLM

### 1.1 Назначение документа

Этот документ предназначен для использования **LLM (Claude)** в роли:

* Lead UX Designer
* Frontend Developer (Vue + Tailwind)
* Backend Developer (Rust)
* System Architect

LLM должен **не придумывать**, а **строго реализовывать описанное поведение, визуал и архитектуру**.

---

### 1.2 Основная цель продукта

Создать **Digital Master Notebook** — цифровой личный рабочий блокнот джазового композитора и аранжировщика с 50+ летним опытом, который:

* максимально **прост для автора** (быстро записывать мысли)
* максимально **глубок и эстетичен для зрителя**
* передаёт **процесс мышления**, а не отшлифованный результат
* выглядит как **культурный артефакт**, а не веб-приложение

---

### 1.3 Ключевые принципы (НЕ НАРУШАТЬ)

LLM **не имеет права**:

* добавлять социальные механики (лайки, комментарии)
* оптимизировать под SEO
* делать “современный SaaS дизайн”
* упрощать визуал до шаблонов
* добавлять лишние настройки

Проект **анти-шумный**, медленный, созерцательный.

---

# 🎭 ЧАСТЬ 2

## 2. Общая концепция UX / UI

### 2.1 Два режима системы

Система **обязательно** состоит из двух режимов:

---

#### ✍️ Master Mode (Private / Author Mode)

Назначение:

* быстрый ввод мыслей
* минимум интерфейса
* отсутствие визуального давления

Характеристики:

* тёмный фон
* минимум декоративных элементов
* UI почти невидим
* акцент на клавиатурный ввод

---

#### 👁 Reader Mode (Public / Viewer Mode)

Назначение:

* спокойное изучение записей
* визуальная глубина
* медленный темп

Характеристики:

* тот же визуальный язык
* но больше воздуха
* плавные анимации
* карточки как экспонаты

---

### 2.2 Основное UX-ощущение

LLM должен проектировать интерфейс так, чтобы пользователь чувствовал:

> «Я листаю чужой рабочий блокнот поздно ночью, в тишине»

---

# 🎨 ЧАСТЬ 3

## 3. Визуальный стиль (ОЧЕНЬ ПОДРОБНО)

### 3.1 Общий вайб

Ассоциации:

* ночь
* студия
* ламповый свет
* бумага
* чернила
* тишина

---

### 3.2 Цветовая палитра (строго)

**Фон**

# 🧩 ЧАСТЬ 4

## 4. Типы записей (Core Data Model)

LLM **НЕ МОЖЕТ** добавлять новые типы без указания.

---

### 4.1 Thought (Мысль)

**Назначение**
Свободный текст. Может быть незавершённым.

**Поля**

* id
* type = THOUGHT
* text (plain text)
* created_at
* optional context

**UI**

* просто текст
* без рамок
* без заголовка

---

### 4.2 Phrase (Музыкальная фраза)

**Содержимое**

* audio OR midi OR notation image
* краткий текст-комментарий

**UI**

* waveform
* кнопка play
* текст ниже

---

### 4.3 Harmony

**Содержимое**

* аккордовая последовательность
* описание функции

**UI**

* моноширинный блок
* без украшений

---

### 4.4 Rhythm

**Содержимое**

* размер
* текстовое описание ощущения

---

### 4.5 Score / Sketch

**Содержимое**

* изображение или PDF
* необработанный скан

---

# 🧭 ЧАСТЬ 5

## 5. Страницы приложения и их функционал (Page-by-Page)

---

## 5.1 Глобальная структура навигации

### 5.1.1 Навигация (обязательные требования)

Навигация **не должна выглядеть как меню сайта**.

Запрещено:

* верхнее меню
* боковой сайдбар
* hamburger-меню

Разрешено:

* минимальная иконка
* жесты
* клавиатура
* почти невидимые элементы

---

### 5.1.2 Основные разделы

Всего **3 основных экрана**:

1. **Notebook Feed** — основной поток записей
2. **Single Note View** — отдельная запись
3. **Create / Edit Note** — ввод контента (Master Mode)

Других страниц **НЕ ДОБАВЛЯТЬ**.

---

## 5.2 Notebook Feed (Главный экран)

### 5.2.1 Назначение

Главный экран — это **лента блокнота**, а не контентная страница.

Он должен:

* выглядеть как поток мыслей
* не иметь начала и конца
* не подталкивать к скроллу

---

### 5.2.2 Поведение при загрузке

* фон тёмный
* контент появляется **постепенно**
* без skeleton loaders
* записи «всплывают» медленно (opacity + translateY)

---

### 5.2.3 Структура экрана

```
[ пустое пространство ]

[ запись ]
[ запись ]

[ больше пустоты ]

[ запись ]

[ + ] (почти незаметная кнопка добавления — только в Master Mode)
```

---

### 5.2.4 Карточки записей (общее)

Карточки:

* без рамок
* без фона
* визуально «лежат» на странице
* имеют разные вертикальные размеры

**Общие элементы:**

* тип записи (иконка или текст, очень тихо)
* дата (мелко, сбоку или снизу)
* основное тело

---

### 5.2.5 Отображение по типам

#### Thought

* крупный текст
* ширина ограничена
* много воздуха

#### Harmony

* моноширинный блок
* выравнивание по левому краю
* без декоративных элементов

#### Phrase

* waveform
* кнопка play (минимальная)
* подпись ниже

#### Rhythm

* размер (например 7/4)
* текст ощущения

#### Score

* превью изображения
* лёгкая тень
* клик → Single Note View

---

### 5.2.6 Фильтрация

Фильтрация **не должна доминировать**.

Реализация:

* скрытая панель
* появляется по жесту / клавише
* фильтры:

    * тип записи
    * период (год)

Никаких:
❌ тегов
❌ сортировки «по популярности»

---

### 5.2.7 Кнопка «Случайная страница»

Небольшая текстовая кнопка:

> Open a page

Поведение:

* открывает случайную запись
* плавный переход
* без перезагрузки страницы

---

## 5.3 Single Note View (Просмотр одной записи)

### 5.3.1 Назначение

Режим **сосредоточенного чтения / просмотра**.

Это **не modal**, а полноценный экран.

---

### 5.3.2 Поведение перехода

* fade out текущей ленты
* fade in записи
* ощущение «приближения»

---

### 5.3.3 Структура экрана

```
[ пустота ]

[ тип записи ]
[ дата ]

[ контент ]

[ ещё пустота ]
```

---

### 5.3.4 Особенности по типам

#### Thought

* увеличенный шрифт
* максимальная читаемость
* без отвлекающих элементов

#### Harmony

* моноширинный текст
* возможность выделять текст
* копирование разрешено

#### Phrase

* большой waveform
* play / pause
* никаких плейлистов

#### Score

* зум
* панорамирование
* без кнопки скачать (по умолчанию)

---

### 5.3.5 Навигация назад

* клик по пустоте
* клавиша ESC
* жест назад (на touch)

---

## 5.4 Create / Edit Note (Master Mode)

### 5.4.1 Общий принцип

Этот экран **должен быть быстрее любого CMS**.

Цель:

> «Открыть → написать → сохранить → уйти»
> за **10 секунд**.

---

### 5.4.2 Вход в режим

Способы:

* кнопка `+`
* горячая клавиша
* специальный URL (private)

---

### 5.4.3 Экран выбора типа

Минимальный экран:

```
[ THOUGHT ] [ HARMONY ] [ PHRASE ] [ RHYTHM ] [ SCORE ]
```

* иконки
* никаких описаний
* мгновенный переход

---

### 5.4.4 Экран ввода (по типам)

#### Thought

* одно большое текстовое поле
* autofocus
* без toolbar
* markdown запрещён

#### Harmony

* textarea с monospace
* перенос строк
* автоформатирование отключено

#### Phrase

* upload audio / midi
* поле комментария

#### Rhythm

* поле размера
* текст ощущения

#### Score

* drag & drop PDF / image
* превью сразу после загрузки

---

### 5.4.5 Сохранение

* автосохранение
* ручная кнопка Save (тихая)
* визуальный индикатор сохранения (очень минимальный)

---

### 5.4.6 Выход

* ESC
* сохранение обязательно
* никаких диалогов «вы уверены?»

---

# ⌨️ ЧАСТЬ 6

## 6. UX ввода контента

### (Клавиатура, жесты, скорость, отсутствие трения)

---

## 6.1 Ключевая цель UX ввода

LLM должен проектировать ввод так, чтобы **автор никогда не думал об интерфейсе**.

Главный KPI:

> от импульса до сохранённой записи — **не более 10 секунд**

---

## 6.2 Общие принципы (НЕ НАРУШАТЬ)

* ❌ никаких модальных окон
* ❌ никаких подтверждений
* ❌ никаких “настроек записи”
* ❌ никаких форматирующих панелей
* ✔ autofocus всегда
* ✔ автосохранение всегда
* ✔ клавиатура — основной инструмент

---

## 6.3 Горячие клавиши (обязательно)

LLM обязан реализовать **следующий набор**:

### Глобальные

* `Cmd / Ctrl + N` → новая Thought
* `Cmd / Ctrl + Shift + N` → выбор типа записи
* `Esc` → выход / назад
* `Cmd / Ctrl + S` → ручное сохранение (тихо)

---

### В режиме ввода

#### Thought

* `Enter` → новая строка
* `Cmd + Enter` → сохранить и закрыть
* `Esc` → сохранить и выйти

#### Harmony

* `Tab` → визуальное выравнивание (НЕ вставка таба)
* `Cmd + Enter` → сохранить

#### Phrase

* drag & drop аудио **в любое место экрана**
* после загрузки → фокус в текст комментария

---

## 6.4 Поведение автосохранения

* автосохранение каждые 2–3 секунды
* без уведомлений
* маленькая точка-индикатор в углу:

    * серый → сохраняется
    * латунь → сохранено

---

## 6.5 Жесты (touch / trackpad)

* свайп вправо → назад
* свайп вниз → закрыть запись
* pinch → зум партитуры

---

## 6.6 Ошибки и сбои

LLM **НЕ ДОЛЖЕН**:

* показывать error popups
* блокировать ввод

Допустимо:

* тихая иконка ошибки
* сохранение локально
* повтор синхронизации позже

---

# 🦀 ЧАСТЬ 7

## 7. Backend архитектура (Rust)

---

## 7.1 Общая архитектура

Backend **минималистичный**, без микросервисов.

Рекомендуемый стек:

* Rust
* Axum
* SQLite (MVP) → PostgreSQL (optional)
* SQLx

---

## 7.2 Архитектурные принципы

* простые CRUD API
* никаких GraphQL
* REST + JSON
* offline-first (поддержка Tauri)

---

## 7.3 Data Model (строго)

### Таблица `notes`

```sql
notes (
  id UUID PRIMARY KEY,
  note_type TEXT,
  content TEXT,
  metadata JSONB,
  created_at TIMESTAMP,
  updated_at TIMESTAMP,
  is_public BOOLEAN
)
```

---

### note_type (enum)

```rust
enum NoteType {
    Thought,
    Harmony,
    Phrase,
    Rhythm,
    Score,
}
```

---

### content

* Thought → plain text
* Harmony → plain text
* Rhythm → plain text
* Phrase → ссылка на audio + текст
* Score → ссылка на файл

---

### metadata (пример)

```json
{
  "duration": 42,
  "time_signature": "7/4",
  "mood": "laid back"
}
```

---

## 7.4 API Endpoints

### GET

* `GET /notes`
* `GET /notes/{id}`
* `GET /notes/random`

---

### POST

* `POST /notes`
* `POST /upload`

---

### PUT

* `PUT /notes/{id}`

---

### DELETE

* `DELETE /notes/{id}` (только private)

---

## 7.5 Аутентификация

* токен в header
* только для Master Mode
* Reader Mode — публичный доступ

---

## 7.6 Хранение файлов

* локально (Tauri)
* сервер → filesystem
* пути хранятся в БД

---

## 7.7 Ошибки API

Ответы **без verbose сообщений**.

```json
{ "status": "error" }
```

Подробности — только в логах.

---

# 🖥 ЧАСТЬ 9

## 9. Tauri Desktop Mode

### Offline-first, ощущение инструмента, а не сайта

---

## 9.1 Назначение Desktop-версии

Desktop-версия **не дополнительная**, а **равноправная**.

Её задачи:

* мгновенный ввод мыслей
* работа без интернета
* локальное хранение
* ощущение «рабочего инструмента»

LLM **НЕ ДОЛЖЕН** воспринимать Tauri как «обёртку сайта».

---

## 9.2 Архитектура Desktop Mode

### 9.2.1 Общая схема

* UI → Vue
* Local API → Rust (Tauri commands)
* Storage → local filesystem + SQLite
* Sync → опционально

---

## 9.2.2 Хранилище

### Локально:

* SQLite база
* папка `notebook_assets/`

    * audio/
    * scores/
    * images/

Все пути — **относительные**.

---

## 9.3 Tauri Commands (обязательные)

```rust
#[tauri::command]
fn create_note(...) {}

#[tauri::command]
fn update_note(...) {}

#[tauri::command]
fn get_notes(...) {}

#[tauri::command]
fn upload_file(...) {}
```

HTTP API **не обязателен** в desktop-режиме.

---

## 9.4 Offline-first поведение

* все записи сохраняются локально
* синхронизация:

    * при запуске
    * по кнопке
* конфликты:

    * побеждает локальная версия
    * без диалогов

---

## 9.5 Глобальные hotkeys (desktop only)

LLM **ОБЯЗАН** реализовать:

* `Cmd + N` → новая Thought (даже если окно свернуто)
* `Cmd + Shift + N` → выбор типа
* `Cmd + `` → показать / скрыть окно
* `Esc` → закрыть текущий экран

---

## 9.6 Поведение окна

* быстрое открытие
* минимальное оформление окна
* тёмный заголовок
* без стандартных кнопок (по возможности)

---

## 9.7 Desktop-только возможности

* drag & drop файлов прямо из Finder
* автозагрузка WAV / PDF
* hi-res аудио
* отсутствие ограничений браузера

---
